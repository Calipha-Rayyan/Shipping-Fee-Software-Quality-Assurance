## 📐 Specification Rules & Decisions

The `ShippingFee(weight, distance, express, member)` function calculates parcel delivery charges based on six specification rules:

1. **Rule 1 (Validation):** If `weight <= 0` or `distance <= 0`, return `INVALID (-1)`.
2. **Rule 2 (Refusal):** If `weight > 50` or `distance > 2000`, return `REFUSED (-2)`.
3. **Rule 3 (Base Fee):** The initial base fee is set to `100`.
4. **Rule 4 (Distance/Weight Surcharge):**
   - If `weight > 10` **AND** `distance > 500`, add `200`.
   - Else if `weight > 10` **OR** `distance > 500`, add `80`.
5. **Rule 5 (Express Delivery):** Express delivery adds `150`, except for members with `weight <= 5`.
6. **Rule 6 (Member Discount):** Registered members receive a 10% discount (`fee -= fee // 10`) when the accumulated fee is at least `250`.

### Decision Predicates Under Test
- **$D_1$:** `weight <= 0 || distance <= 0`
- **$D_2$:** `weight > 50 || distance > 2000`
- **$D_3$:** `weight > 10 && distance > 500`
- **$D_4$:** `weight > 10 || distance > 500`
- **$D_5$:** `express && (!member || weight > 5)`
- **$D_6$:** `member && fee >= 250`

### Key Fault Analysis:
- **Active Clause Power:** CACC and RACC detected **7 out of 10 faults**, more than double the structural criteria (NC/EC/PC: 3 kills).
- **Sub-Clause Masking:** Faults $f_{02}, f_{04}, f_{05}, f_{07}$ survive branch coverage because coarse criteria accept short-circuited tests where the faulty clause is masked.
- **Off-by-One Boundaries ($f_{03}, f_{08}$):** Survive all 6 criteria because structural criteria mandate *which paths or clauses to visit*, not *which boundary values to choose*.
- **Equivalent Mutant ($f_{10}$):** $\forall w \in \mathbb{Z}: (w > 50) \iff (w \ge 51)$. Produces identical outputs for all integer inputs; impossible to kill.
- **Mutant 13 vs $f_{10}$:** In contrast to $f_{10}$, Mutmut Mutant 13 (`weight > 51`) is **non-equivalent** to `weight > 50` and is distinguished by $weight = 51$.

## 🚀 Reproduction & Execution Guide

### 1. Python Environment Setup & Execution
```bash
cd python
python -m venv .venv
source .venv/bin/activate       # On Windows PowerShell: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# Run all 37 unit tests against the reference implementation
python -m unittest discover -s tests -p "test_*.py" -v

# Run the complete fault-detection matrix
python run_matrix.py

# Measure statement and branch coverage
coverage run --branch --source=. -m unittest tests.test_racc
coverage report -m --include=shipping_ref.py

# Verify MC/DC dynamic requirements
python -m pymcdc --unittest tests/test_racc.py shipping_ref.py

# Verify predicate CSV files
python tools/predcheck.py check "express && (!member || weight > 5)" predcheck_csvs/d5.csv
```

### 2. Java Environment Setup & Execution
```bash
cd java

# Compile main and test classes
javac -d out/classes src/main/java/shipping/*.java
javac -cp "out/classes;lib/junit-4.13.2.jar;lib/hamcrest-core-1.3.jar" -d out/test src/test/java/shipping/*.java

# Run all 37 JUnit 4 tests
java -cp "out/classes;out/test;lib/junit-4.13.2.jar;lib/hamcrest-core-1.3.jar" \
     org.junit.runner.JUnitCore \
     shipping.NodeCoverageTest shipping.EdgeCoverageTest shipping.PredicateCoverageTest \
     shipping.ClauseCoverageTest shipping.CorrelatedActiveClauseCoverageTest \
     shipping.RestrictedActiveClauseCoverageTest shipping.ExtraTest

# Run the Java fault-detection matrix
java -cp "out/classes;out/test;lib/junit-4.13.2.jar;lib/hamcrest-core-1.3.jar" shipping.RunMatrix

# Generate Bytecode CFG
python tools/bytecode_cfg.py out/classes shipping.ShippingRef fee > fee.dot
dot -Tpng fee.dot -o fee.png
```
